# 6장 — 스코프 / 형변환

---

## 스코프: 이 두 코드의 차이

```java
// Scope3_1                      // Scope3_2
int m = 10;                      int m = 10;
int temp = 0;      ←── 밖        if (m > 0) {
if (m > 0) {                         int temp = m * 2;   ←── 안
    temp = m * 2;                    System.out.println(temp);
    System.out.println(temp);    }
}
```

<br>

**결과는 똑같습니다. 그런데 오른쪽이 맞습니다.**

🎤 "왼쪽은 `temp`가 메서드 끝까지 살아있어요. 300줄짜리 메서드에서 아래쪽 누가 `temp` 또 쓰면? 그때부터 추적이 안 됩니다."

---

## 원칙

# 변수는 **가장 좁은 범위**에 선언한다

<br>

- 스코프를 벗어나면 컴파일 에러 → **컴파일러가 실수를 대신 잡아준다**
- 넓게 선언하면 그 안전장치를 스스로 끄는 것

🎤 "IDE가 'temp를 안쪽으로 옮길 수 있습니다' 하고 알려주는 게 이 얘기입니다."

---

## 형변환: 이건 몇일까요?

```java
double result = 3 / 2;
System.out.println(result);
```

<br>

🎤 (3초 기다린다)

<br>

## → **`1.0`**

🎤 "저도 이 강의 듣기 직전에 1.5라고 답했습니다."

---

## 왜 1.0인가

```java
double result = 3 / 2;
                └─┬─┘
              ① int / int → int 1   (여기서 소수점이 이미 버려짐)
         ②    1 → 1.0 으로 자동 형변환
```

<br>

**`double`은 결과를 담는 그릇일 뿐. 그릇이 크다고 버려진 값이 되살아나지 않습니다.**

```java
int div1        = 3 / 2;            // 1
double div2     = 3 / 2;            // 1.0  ← 함정
double div3     = 3.0 / 2;          // 1.5
double div4     = (double) 3 / 2;   // 1.5
```

🎤 "규칙 하나만 기억하면 됩니다. **피연산자**를 바꿔야지, 대입 대상은 아무 소용 없다."

---

## 실무에서 터지는 자리

```java
int 정답수 = 3, 전체 = 4;
double 정답률 = 정답수 / 전체 * 100;   // 0.0
```

<br>

- 통계·정답률·전환율·평균이 전부 **0으로 찍힘**
- 에러가 없어서 **한참 뒤에 발견됨**

🎤 "로그에 0.0이 쭉 찍히는데 예외는 안 나요. 데이터가 없는 건지 계산이 틀린 건지부터 의심하게 됩니다."

---

## 그리고 오버플로우

```java
int max = 2147483647;   // int 최댓값 (약 21억)
System.out.println(max + 1);
```

<br>

## → **`-2147483648`**

<br>

시계처럼 한 바퀴 돌아 **최솟값**으로 떨어집니다.

```
... 2147483646 → 2147483647 → -2147483648 → -2147483647 ...
                              └── 예외 없음. 조용히 음수 ──┘
```

🎤 "**int 오버플로우는 터지지 않습니다. 조용히 틀립니다.**"

---

## 그래서 이건 문법이 아니라 **보안 점검 항목**입니다

<br>

제가 유지보수하는 웹 시스템에는
**모든 요청 파라미터의 숫자 크기를 검사하는 인터셉터**가 있습니다.

<br>

- 상한을 넘는 숫자가 들어오면 **요청 자체를 차단**
- **SQL Injection 검사와 같은 자리**에서 같은 등급으로 처리

<br>

🎤 "입문편 6장에서 배운 내용이, 실무에서는 취약점 점검 항목으로 돌아왔습니다."

> ⚠️ 회사/발주처 코드는 화면에 띄우지 말 것. 클래스명·경로·도메인 언급 금지.

---

## 검증 로직 (구조만 재현)

```java
// 파라미터 값이 순수 숫자라면
if (value.matches("^[0-9]+$")) {

    // ① 자릿수부터 비교한다
    if (value.length() > MAX.length()) return 차단;

    // ② 그 다음에야 숫자로 바꾼다
    if (Integer.parseInt(value) > Integer.parseInt(MAX)) return 차단;
}
```

<br>

# 왜 ①이 먼저일까요?

🎤 (3초 기다린다 — 이게 이 발표의 하이라이트)

---

## `Integer.parseInt("9999999999")`

<br>

## → **`NumberFormatException`**

<br>

int 범위를 넘는 문자열은 숫자로 바꿀 수조차 없습니다.

<br>

# **오버플로우를 막는 코드가**
# **오버플로우 때문에 죽습니다.**

<br>

🎤 "그래서 자릿수로 먼저 걸러낸 다음에야 변환합니다."

---

## 상한을 21억이 아니라 **9자리**로 잡은 이유

<br>

```
MAX = "999999999"   ← 9자리

자릿수 검사를 통과한 값 = 최대 999,999,999
int 최댓값             =   2,147,483,647
                          └── 항상 안전 ──┘
```

<br>

**`int`가 21억까지라는 사실을 모르면 이 숫자를 이렇게 정할 수 없습니다.**

🎤 "입문 문법 하나가 방어 로직의 설계 근거가 된 겁니다."

---

## 덧붙여 — 숫자처럼 생겼다고 다 숫자가 아닙니다

<br>

검사에서 **제외**하는 파라미터들:

```
tel, phone, ...
```

<br>

전화번호는 숫자로만 이루어져 있지만 **크기에 의미가 없습니다.**
막으면 정상 사용자가 전화번호를 못 넣습니다.

<br>

🎤 "실무 검증은 '막는 것'보다 '무엇을 안 막을지'가 더 어렵습니다."

> 시간 부족하면 이 슬라이드를 제일 먼저 뺄 것.

---

## 그래서 실무 규칙

<br>

- 금액·누적값·조회수는 **`long`** (소수 계산이 필요하면 `BigDecimal`)
- 사용자 입력 숫자는 **서버에서 상한/하한 검증**
- 나눗셈 전에 **피연산자 타입 확인**

<br>

🎤 "6장은 강의에서 제일 짧은 단원입니다. 그런데 실무에서 제일 조용하게 사고 칩니다."

# 9장 — 메서드

---

## 신입이 가장 오래 헤매는 버그

```java
int num1 = 5;
changeNumber(num1);
System.out.println(num1);   // 10일까?

public static int changeNumber(int num2) {
    num2 = num2 * 2;
    return num2;
}
```

<br>

## → **`5`**

🎤 "분명 메서드 안에서 2배로 만들었는데 왜 그대로지? 이거 붙잡고 반나절 씁니다."

---

## 값이 **복사**되기 때문

```java
num1 = changeNumber(num1);   // ← 반환값을 다시 대입해야만 바뀐다
```

<br>

```
main()                   changeNumber()
┌──────────┐             ┌──────────┐
│ num1 = 5 │  ──복사──▶  │ num2 = 5 │
└──────────┘             └────┬─────┘
                              │ × 2
                         ┌────▼─────┐
                         │ num2 = 10│  ← 여긴 바뀌지만
                         └──────────┘     main의 num1과 무관
```

🎤 "메서드는 원본이 아니라 **복사본**을 받습니다."

---

## 그런데 배열을 넘기면

```java
int[] arr = {1, 2, 3};
changeArray(arr);
System.out.println(arr[0]);   // 1? 100?

public static void changeArray(int[] a) {
    a[0] = 100;
}
```

<br>

## → **`100`. 바뀝니다.**

<br>

# 같은 "전달"인데 왜 결과가 다를까요?

⚠️ 확인필요 — 9장 강의의 실제 예제 파일명/코드로 교체 (`array/Array1Ref*.java`)

---

## 스택과 힙

```
        스택                         힙
┌────────────────┐          ┌─────────────────┐
│ arr  = x001 ───┼─────────▶│ [1, 2, 3]       │
├────────────────┤     ┌───▶│                 │
│ a    = x001 ───┼─────┘    └─────────────────┘
└────────────────┘
   주소값을 복사했을 뿐,        가리키는 실체는 하나
   둘 다 같은 곳을 본다
```

<br>

**기본형은 값을 복사, 참조형은 주소를 복사.**
**어느 쪽이든 "복사"라는 사실은 같습니다.**

---

## 🧩 퀴즈 — 그리고 떡밥 회수

<br>

# 자바는 call by value일까요, call by reference일까요?

<br>

## → 자바에는 **call by value밖에 없습니다**

배열을 넘겼을 때 값이 바뀌는 건
**"참조값을 복사해서" 넘겼기 때문**이지, call by reference가 아닙니다.

🎤 "이게 오늘 발표에서 딱 하나만 가져가실 내용입니다."

- → **실전 자바 기본편**

🎤 "완주 스터디니까 — 다음 강의를 왜 들어야 하는지가 이 강의의 마지막 메시지입니다."
