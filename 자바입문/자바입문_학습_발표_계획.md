## 2. 수강 전략

### 핵심 판단: 순서를 뒤집는다

교재 순서대로 1→9장을 가면 발표 핵심 재료인 8·9장을 **일요일 밤에야** 만나게 된다. 그때 발표자료를 만들기 시작하면 시간이 없다.

> **발표에 쓸 단원(6·8·9장)을 토요일에 먼저 듣고, 이미 아는 1~5장을 일요일에 흘려듣는다.**

자바 입문은 순차 의존성이 있지만, 실무에서 스프링을 쓰고 있어 변수·조건문·반복문 지식이 이미 있으므로 순서를 뒤집어도 막히지 않는다.

## 4. 발표 구성

### 채택한 뼈대

> 중요 단원 선정 → 왜 중요한가(학습적/실무적) → 내용 간단 발표 → 실물 데모 → 퀴즈

### 세 가지 보완 원칙

**① 단원은 정확히 3개로 제한 (6장·8장·9장)**
4개 이상 잡으면 각 단원에 3분도 못 준다. 전부 얕아지고 목차 읽기가 된다.

**② 퀴즈를 마지막에 몰지 않는다**
- 발표는 거의 항상 시간이 밀린다 → 마지막 블록이 잘리면 퀴즈가 통째로 날아간다
- 20분 내내 듣기만 한 사람은 마지막 5분엔 이미 집중이 끊겨 있다

→ **각 단원 끝에 퀴즈 1개씩** 배치, 마지막엔 종합 1~2개.
→ 도입부에 퀴즈 1개를 **떡밥**으로 던지고 마지막에 회수한다.

**③ "실무적으로 중요"를 추상적으로 말하지 않는다**
"메서드는 재사용성이 좋습니다" 같은 말은 아무도 안 듣는다. **구체적인 실패 사례**로 말할 것. 실무 경험이 최대 무기다.

## 5. 단원별 발표 앵글

### 6장 — 스코프, 형변환

- **학습적**: 변수의 생명주기, 타입 변환 시 값 손실
- **실무적**:
  - `int / int` 정수 나눗셈으로 **평균·비율이 0으로 나오는 버그**
  - `int` 오버플로우(약 21억) — 금액 누적 계산에서 터짐
- **데모**: `자바 입문 소스코드/src/casting/Casting1~4.java`

### 8장 — 배열

- **학습적**: 첫 자료구조. 인덱스 기반 사고
- **실무적**: List/Collection의 기반. 결정적으로 —
  `ProductAdminEx.java`에서 `productNames`와 `productPrices` **배열 2개가 인덱스로만 묶여 있다.**
  여기서 가격순 정렬을 한 번 하면 이름과 가격이 어긋난다.
  → **"객체가 왜 필요한가"의 가장 좋은 설명**
- **데모**: `자바 입문 소스코드/src/array/ex/ProductAdminEx.java` 실행

```java
// ProductAdminEx.java — 배열 2개로 상품 관리 (한계 지점)
String[] productNames = new String[maxProducts];
int[] productPrices = new int[maxProducts];
int productCount = 0;
```

### 9장 — 메서드 (클라이맥스)

- **학습적**: call by value
- **실무적**: "분명 메서드에서 바꿨는데 왜 값이 그대로지?" — 신입이 가장 오래 헤매는 디버깅
- **핵심 대비**: 기본형을 넘기면 안 바뀌는데, 배열을 넘기면 바뀐다.
  **같은 "전달"인데 결과가 다르다** → 여기서 스택/힙 그림 하나
- **데모 순서**: `method/MethodValue1~3.java` → `array/Array1Ref1~4.java`

```java
// MethodValue3.java — 값을 되돌려받아야만 한다
int num1 = 5;
num1 = changeNumber(num1);   // 반환값 대입이 없으면 num1은 그대로

public static int changeNumber(int num2) {
    num2 = num2 * 2;
    return num2;
}
```

### 마무리

배열 2개로 상품을 관리하는 구조의 한계(이름과 가격이 인덱스로만 묶임)
→ 그래서 다음이 **클래스**
→ 실전 자바 기본편으로 이어짐

**완주 스터디 발표로서 "그래서 다음 강의를 왜 들어야 하는가"로 자연스럽게 끝난다.**

## 6. 퀴즈 초안

### Q1 (떡밥 — 도입에서 던지고 9장에서 회수)
자바는 call by value인가요, call by reference인가요?

### Q2 (6장 직후)
`System.out.println(3 / 2);` 의 출력은? 왜 그럴까요?

### Q3 (8장 직후)
`int[] arr = new int[3];` 선언 직후 `arr[0]`의 값은?

### Q4 (9장 직후)
메서드에 `int`를 넘겨서 안에서 바꾸면 호출한 쪽 값이 바뀔까요? 배열을 넘기면요?

### Q5 (종합)
상품 이름 배열과 가격 배열을 가격순으로 정렬하려면 무엇이 문제일까요?

---

### 💡 답

**Q1.** call by value만 있다. 배열을 넘겼을 때 값이 바뀌는 건 **"참조값을 복사해서" 넘겼기 때문**이지 call by reference가 아니다.

**Q2.** `1`. int끼리의 연산 결과는 int라 소수점이 버려진다.

**Q3.** `0`. 배열은 생성 시 타입별 기본값으로 자동 초기화된다.

**Q4.** int는 안 바뀌고 배열은 바뀐다. (Q1과 연결)

**Q5.** 두 배열이 인덱스로만 연결돼 있어 한쪽만 정렬하면 짝이 깨진다. 그래서 클래스가 필요하다.

> Q1을 떡밥으로 쓰는 것이 핵심. 발표 전체가 "그 질문에 답하러 가는 길"이 되고, 마지막에 회수하면 구성이 닫힌다.
