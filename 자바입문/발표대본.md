## 2. 같은 결과를 내는 두 코드, 그런데 하나는 나쁘다 · 1:00

> 먼저 스코프입니다. 지역 변수는 자신이 선언된 코드 블록, 중괄호 안에서만 생존하고 블록을 벗어나면 제거됩니다. 벗어나서 접근하면 `cannot find symbol` 컴파일 오류가 나요. 이렇게 변수에 접근할 수 있는 범위를 스코프라고 합니다.
> 그런데 이런 개념이 왜 필요할까요? 두 코드를 보시죠. **결과는 완전히 똑같습니다.** `temp` 를 어디에 선언했느냐만 다릅니다.
> 강의에서는 왼쪽이 좋은 코드가 아니라고 말합니다. 이유가 두 가지예요.
> 첫째, 메모리. `temp` 는 if 안에서만 필요한데 main 이 끝날 때까지 남아 있습니다.
> 둘째, 이게 더 중요한데 — 코드 복잡성입니다. if 가 끝나도 어디서나 `temp` 에 접근할 수 있으니, 유지보수할 때 `m` 뿐 아니라 `temp` 까지 계속 신경 써야 합니다. 지금은 코드가 짧아서 와닿지 않지만 실무에서는 훨씬 복잡하죠.
> 6장 전반부의 결론은 이 문장입니다. (인용 읽기)
> **"좋은 프로그램은 무한한 자유가 있는 프로그램이 아니라, 적절한 제약이 있는 프로그램이다."**

**강조**

## 3. double 에 담았는데 왜 1.0 인가 · 1:00

> 이제 형변환입니다. 질문 하나 드리겠습니다. `double div = 3 / 2;` 이때 div 는 얼마일까요?
> (3초 기다린다)
> **1.5 가 아니라 1.0 입니다.**
> 규칙은 두 개뿐입니다. 같은 타입끼리 계산하면 같은 타입이 나온다. 다른 타입끼리면 큰 범위로 자동 형변환된다.
> `3 / 2` 는 int 끼리니까 결과가 int 인 1 입니다. 소수점은 이 시점에 **이미** 버려졌어요. 그 1이 double 변수에 들어가면서 1.0 이 된 겁니다. 아래 블록이 그 단계입니다.
> 결과를 담는 변수의 타입이 아니라 **피연산자의 타입**이 계산 결과를 결정합니다.
> 소수까지 구하고 싶으면 `(double) 3 / 2` 처럼 피연산자 쪽을 명시적으로 형변환해야 합니다. 이게 **명시적 형변환**, 캐스팅이고요.

**강조**
- **반드시 물어보고 3초 기다리세요.** 답을 바로 말하면 이 슬라이드는 힘을 잃습니다.
- (선택) "저도 강의 듣기 직전에 1.5 라고 답했습니다" — 본인 경험을 넣으면 훨씬 잘 붙습니다.

## 4. int 최고값보다 1 큰 수를 담으면 · 0:50

> 형변환에서 생기는 문제는 두 가지입니다. 하나는 방금 본 소수점 버림, 다른 하나가 오버플로우입니다.
> int 최고값은 21억 4748만 3647 입니다. 여기까지는 long 에서 int 로 캐스팅해도 아무 문제 없습니다.
> 그런데 1 큰 수를 int 로 캐스팅하면 — 결과가 **마이너스 21억**이 됩니다.
> int 에는 이 숫자를 표현할 방법이 없어요. 범위를 초과하면 전혀 다른 숫자가 나오는데, 이걸 오버플로우라고 합니다. 시계가 한 바퀴 돈 것처럼 처음부터 다시 시작하는 거죠.
> 중요한 건 이겁니다. **예외도 안 나고 컴파일 오류도 안 납니다.** 그냥 조용히 틀린 값으로 계속 굴러갑니다.
> 강의에서는 이렇게 말합니다. 결과가 어떻게 되는지 계산하는 데 시간을 낭비하지 마라, 오버플로우 자체가 발생하지 않도록 막아야 한다.

**강조**
- `-2147483648` 을 손으로 가리키며 말하세요. 숫자 자체가 설득력입니다.
- "**예외도 컴파일 오류도 나지 않는다**" — 다음 슬라이드로 가는 다리입니다.

## 5. 그래서 실무에서는 숫자를 "막는다" · 1:10 【본인 사례 — 핵심】

> 강의는 여기서 끝나지만, 저는 이 문장을 실무에서 그대로 만났습니다.
> 제가 유지보수하는 웹 시스템에는 모든 요청 파라미터의 숫자 크기를 검사하는 인터셉터가 있습니다. 상한을 넘는 숫자가 들어오면 요청 자체를 차단해요.
> 그리고 이 검사가 **SQL Injection 검사와 같은 자리에서, 같은 등급으로** 처리됩니다. 입문 문법인 줄 알았던 게 실무에서는 보안 점검 항목이었던 겁니다.
> 오른쪽이 검증 로직인데, 구조만 재현했습니다. 순수 숫자인지 확인하고, ① 자릿수를 먼저 비교하고, ② 그 다음에야 숫자로 바꿉니다.
> 왜 자릿수를 먼저 볼까요?
> (3초 기다린다)
> 바로 변환하면 `Integer.parseInt("9999999999")` 가 int 범위를 넘어서 예외가 납니다. **오버플로우를 막으려는 코드가, 오버플로우 때문에 죽는 거죠.**
> 그래서 자릿수로 먼저 걸러낸 다음에 변환합니다. int 가 21억까지라는 사실을 모르면 이 순서를 이렇게 짤 수 없습니다.
> 덧붙이면, 전화번호처럼 숫자로만 이루어졌지만 크기에 의미가 없는 값은 검사에서 제외합니다. 실무 검증은 무엇을 막을지보다 **무엇을 안 막을지**가 더 어렵습니다.

**강조**
- **슬라이드를 보지 말고 말로 하세요.** 실제 겪은 일이라 가장 힘이 센 구간입니다.
- "왜 자릿수를 먼저 볼까요?"에서 **반드시 3초.** 이 발표의 하이라이트입니다.
- ⚠️ 회사·발주처 코드는 화면에 띄우지 마세요. 클래스명, 경로, 도메인은 언급하지 않습니다.

## 6. 학생이 100명이면 변수도 100개 · 0:50

> 8장 배열입니다.
> 왼쪽은 학생 다섯 명의 점수입니다. 학생이 늘어나면 코딩 양이 그대로 비례해서 늘어나요. 100명이면 int 변수를 100개 선언해야 합니다.
> 반복문으로 해결하면 될 것 같은데 안 됩니다. **변수 이름이 전부 다르기 때문입니다.**
> 이 문제를 해결하는 게 배열입니다. 같은 타입의 변수를 쓰기 편하게 하나로 묶어둔 것.
> 아래 세 가지만 기억하시면 됩니다.
> `new int[5]` 로 int 변수 5개가 만들어지고, 내부 값이 **자동으로 초기화**됩니다. 숫자는 0, boolean 은 false, String 은 null.
> 그리고 인덱스는 **0부터** 시작합니다. 5개를 만들었으면 0부터 4까지. 5를 쓰면 `ArrayIndexOutOfBoundsException` 이 납니다.
> 마지막으로, 배열을 생성하면 자바가 그 배열에 접근할 수 있는 **참조값**, 주소를 돌려줍니다. 배열 변수는 그 주소를 보관하는 거예요.

**강조**
- "변수 이름이 달라서 반복문을 못 쓴다"가 배열이 등장하는 결정적 이유입니다.
- 자동 초기화 값과 인덱스 시작. **둘 다 퀴즈로 나갑니다.**
- 마지막 참조값 문장이 다음 슬라이드로 이어집니다.

## 7. 값을 담느냐, 주소를 담느냐 · 0:40 【밀리면 30초로 압축】

> 여기서 자바 변수의 큰 분류가 나옵니다.

> `int[] students` 처럼 데이터에 접근하기 위한 주소를 저장하는 걸 **참조형**이라고 합니다.
> 왜 배열은 굳이 복잡하게 참조형을 쓸까요? 크기를 **동적으로** 정할 수 있기 때문입니다. 아래 코드처럼 사용자가 입력한 값이 size 에 들어가면, 이 코드가 실행되는 시점에 배열 크기가 정해집니다. 기본형은 이게 안 돼요.
> 참고로 뒤에서 배우는 객체와 클래스도 전부 참조형입니다.

**강조** — 마지막 문장. 8장이 다음 강의로 이어지는 지점입니다.

## 10. 자바는 항상 변수의 값을 복사해서 대입한다 · 1:00 【핵심】

> 여기서 자바의 아주 중요한 대원칙이 나옵니다. 강의에서는 "밑줄 100번 긋자"고 표현합니다.
> **자바는 항상 변수의 값을 복사해서 대입한다.**
> 코드를 보시죠. `num1` 이 5입니다. 이걸 `changeNumber` 에 넘겨서 안에서 2배를 곱합니다. 호출이 끝난 뒤 `num1` 은 얼마일까요?
> (3초 기다린다)
> **5입니다.** 10이 아닙니다.
> `num1` 의 값 5를 **읽어서 복사해서** `num2` 에 전달한 겁니다. `num2` 는 10이 됐지만 `num1` 과는 아무 관계가 없어요. 완전히 다른 변수니까요.
> 실행 결과를 보시면 3번에서 num2 는 10인데, 4번에서 num1 은 여전히 5입니다.
> 신입 때 "분명 메서드에서 바꿨는데 왜 값이 그대로지?" 하고 반나절 붙잡는 게 정확히 이겁니다.

**강조**
- **반드시 결과를 먼저 예측하게 하세요.** 이 발표에서 하나만 가져간다면 이 슬라이드입니다.

## 11. 그러면 어떻게 값을 바꾸는가 — 반환값을 받는다 · 0:50

> 답은 단순합니다. **반환값을 받아서 다시 대입하면 됩니다.**
> `num1 = changeNumber(num1);` — 이 대입이 있어야 10이 됩니다. 이게 빠지면 그대로 5예요.
> 오른쪽은 메서드의 또 다른 실무적 가치입니다. 입금과 출금 로직을 `deposit`, `withdraw` 메서드로 뽑아내면, main 이 세세한 코드가 아니라 **전체 구조를 한눈에** 보여줍니다. 책의 목차를 보는 것 같죠.
> 이런 리팩토링을 **메서드 추출**, Extract Method 라고 합니다. 여기서 중요한 건 **재사용이 목적이 아니어도 괜찮다**는 겁니다. 적절히 분류하기만 해도 읽기 쉽고 유지보수하기 좋은 코드가 되고, 변경이 생겨도 그 메서드만 고치면 되니 수정 범위가 한정됩니다.
> 마지막으로 하나. `main` 도 사실은 메서드입니다. 각 메서드 안의 변수는 **이름이 같아도** 서로 완전히 분리된 다른 변수예요.
> 그리고 아까 배운 참조형, 배열을 넘길 때도 원칙은 똑같습니다. 참조값을 복사해서 전달하는 겁니다. 자세한 건 다음 강의에서 다룹니다.

## 예상 질문과 답

**Q. MAX 를 왜 숫자가 아니라 문자열로 들고 있나요?**
> 숫자로 바꾸는 순간이 위험하기 때문입니다. 문자열로 두면 `length()` 로 자릿수를 먼저 볼 수 있고, 그 검사를 통과한 값만 변환하니 `parseInt` 가 터질 일이 없습니다.

**Q. 그냥 상한을 int 최댓값(2147483647)으로 두면 안 되나요?**
> 그러면 10자리가 되어서, 같은 10자리인 9999999999 가 자릿수 검사를 통과해 `parseInt` 에서 예외가 납니다. 9자리로 잡으면 통과한 값이 최대 999,999,999 라 항상 안전합니다.

**Q. 배열을 메서드에 넘기면 안에서 바꾼 게 반영되나요?**
> 반영됩니다. 다만 그건 call by reference 라서가 아니라 **참조값을 복사해서** 넘겼기 때문입니다. 원칙은 그대로예요. 이 부분은 입문편 범위 밖이고 다음 강의에서 다룹니다.

**Q. 오버플로우를 막는 다른 방법은 없나요?**
> 강의에서는 가장 단순한 해법으로 대입하는 변수의 타입을 int 에서 long 으로 늘리는 것을 제시합니다. 실무에서는 거기에 더해 입력값 검증을 겁니다.

**Q. 향상된 for문(for-each)은 안 다루나요?**
> 8장에 나옵니다. 인덱스와 종료 조건 없이 배열을 순회할 수 있어서 간결한데, 인덱스 값을 직접 써야 하는 경우에는 쓸 수 없습니다. 시간 관계상 뺐습니다.
