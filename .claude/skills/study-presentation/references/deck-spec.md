# 덱 스펙(JSON) 작성법

발표자료와 대본의 **단일 원본**. 전체 예시는 [../examples/java-start.deck.json](../examples/java-start.deck.json).

## 최상위 구조

```json
{
  "meta": { ... },
  "output": { "dir": ".", "name": "김영한_스프링입문_발표", "script": "발표대본.md" },
  "slides": [ { "type": "...", ... } ],
  "rehearsal": [ "리허설 체크 항목", ... ]
}
```

### meta

| 필드 | 설명 |
|---|---|
| `title` | 발표 제목 (대본 md 제목) |
| `style` | 스타일 버전 (`"v1"` 등, 생략 시 `v1`) — [styles/README.md](styles/README.md) |
| `course` | 강의 전체 이름 — 표지 소제목 |
| `presenter` | 표지 하단 (발표일은 넣지 않는다 — `date` 필드 사용 금지) |
| `scope` | 다룬 범위 (예: `"2·4·6장"`) — 대본 머리말의 "PDF 범위 안에서만" 문구 |
| `runtime` | 목표 러닝타임 문자열 (예: `"11~12분"`) |
| `compress` | 시간이 밀릴 때 압축할 슬라이드 안내 (대본에 표시) |

### output

| 필드 | 기본값 | 설명 |
|---|---|---|
| `dir` | `"."` | 스펙 파일 기준 출력 폴더 |
| `name` | `"발표자료"` | pptx 파일명(확장자 제외) |
| `script` | `"발표대본.md"` | 대본 파일명 |

## 텍스트 표기 (모든 문자열 필드 공통)

| 표기 | 결과 |
|---|---|
| `**구절**` | 강조 — 제목에선 파란색, 본문에선 파란 굵은 글씨, 파란 카드 위에선 흰색 굵은 밑줄 |
| `` `코드` `` | 인라인 코드 — Consolas |
| `\n` | 줄바꿈 |

## 모든 슬라이드 공통 필드

| 필드 | 설명 |
|---|---|
| `type` | 슬라이드 유형 (아래 표) — **필수** |
| `eyebrow` | 제목 위 소제목. 관례: `"06  스코프, 형변환"` (단원 번호 + 공백 2칸 + 단원명) |
| `accent` | `true`면 소제목을 파란색으로 (`case`는 자동) |
| `title` | 슬라이드 제목 — **단어 위주로 간결하게**, 1줄. 반말 문장 금지 |
| `lead` | 제목 아래 **질문·핵심 문장 띠**(22pt, 1줄 권장). 본문은 그만큼 아래로 내려간다. `code-compare`·`code-explain`·`cards`·`image` 에서 사용 |
| `label` | 대본·시간표에 쓸 짧은 이름 (없으면 제목에서 `**` 제거해 사용) |
| `time` | 발표 시간 `"0:50"` — **필수** |
| `tag` | 대본 표시용 태그. `핵심` `실무` `데모`가 들어가면 시간표에서 굵게 |
| `script` | 대사 배열(한 줄 = 한 호흡) — **필수**. 규칙은 [script-format.md](script-format.md) |
| `cues` | 연출 지시 배열 (3초 기다리기, 그대로 읽기 등) |

## 코드 블록 필드

`code`는 문자열, 객체, 또는 **배열**(여러 블록을 위에서 아래로 쌓음)이다.

```json
"code": "int a = 1;",
"code": { "label": "before", "lang": "java", "code": "int a = 1;" },
"code": [ "int a = 1;", { "label": "계산 단계", "code": "..." } ],
"output": "실행 결과 텍스트"
```

- `lang`: `java`(기본) · `gradle` · `html` · `sql` · `properties` · `yaml` · `output`
- `output`은 코드 블록들 아래에 실행 결과 블록으로 붙는다 (숫자만 파란색).
- 쌓인 블록은 **같은 글자 크기**로 맞춰진다. 12pt로도 안 들어가면 빌드 경고.
- 들여쓰기는 공백 4칸. JSON 안에서 줄바꿈은 `\n`, 큰따옴표는 `\"`.

## 유형별 필드

### `cover` — 표지 겸 목차
| 필드 | 설명 |
|---|---|
| `title` | **강좌명 그대로** (예: `"스프링 입문"`). 문장형 제목 금지 |
| `subtitle` | 한 줄 부제 |
| `agenda` | `[{ "no": "06", "title": "스코프, 형변환", "desc": "한 줄 설명" }]` 2~4개 |
| `extra` | 카드 아래 한 줄 (예: `"+ 마지막에 퀴즈 5문제"`) |

### `statement` — 큰 한 문장
| 필드 | 설명 |
|---|---|
| `text` | 40pt, 2줄까지. 질문이면 답을 다음 슬라이드로 |
| `sub` | 아래 회색 한 줄 |

### `code-compare` — before / after
| 필드 | 설명 |
|---|---|
| `left`, `right` | 코드 블록 (`label` 권장: `"before"`, `"after"`) |
| `points` | `[{ "head", "body" }]` 최대 2개 — 각 코드 아래 |
| `callout` | 맨 아래 결론 박스 (문자열 또는 `{ "text", "label", "style" }`) |

### `code-explain` — 코드 왼쪽, 설명 오른쪽
| 필드 | 설명 |
|---|---|
| `code`, `output` | 왼쪽 열 (폭 6.9in) |
| `bullets` | 오른쪽 불릿 2~4개 |
| `keyline` | 오른쪽 굵은 결론 문장 |
| `note` | 오른쪽 회색 보충 문장 |
| `callout` | (선택) 맨 아래 전체 폭 결론 박스 |

### `case` — 실무 사례
소제목이 자동으로 파란 `실무`가 된다.
| 필드 | 설명 |
|---|---|
| `bullets`, `keyline`, `note` | 왼쪽 열 (폭 6.0in) |
| `code`, `output` | 오른쪽 열 — 전체 높이 사용 |
| `question` | `{ "q": "왜 자릿수를 먼저 볼까?", "a": "답 문장" }` — 왼쪽 열 아래 박스 |

### `cards` — 개념 카드
| 필드 | 설명 |
|---|---|
| `code` | (선택) 위쪽 전체 폭 코드 |
| `cards` | `[{ "head", "body", "accent" }]` 2~4개. `accent: true` 면 파란 카드(권장·정답 강조). 3장 이하면 본문 16pt |
| `keyline` | 카드 아래 결론 문장 |

### `contrast` — 두 개념 대비
| 필드 | 설명 |
|---|---|
| `left` | 회색 카드 `{ "head", "sub", "body": [] }` — `sub`은 코드 글꼴 한 줄 |
| `right` | **파란 카드** (강조하고 싶은 쪽을 오른쪽에) |
| `code` | (선택) 아래 전체 폭 코드 |

### `principle` — 핵심 원칙 (덱당 1장 권장)
| 필드 | 설명 |
|---|---|
| `title` | 36pt, 3줄까지 (`\n`으로 끊기) |
| `quote` | 제목 아래 회색 인용 |
| `code`, `output` | 오른쪽 열 |
| `keyline` | 맨 아래 **파란 결론 카드** |

### `image` — 그림 + 설명
| 필드 | 설명 |
|---|---|
| `image` | `{ "path": "img/mvc.png", "caption": "출처: 강의자료 2장", "alt": "대체 텍스트" }` — 경로는 스펙 파일 기준 |
| `bullets`, `keyline`, `note` | 있으면 그림 왼쪽(7.4in) + 설명 오른쪽, 없으면 그림 전체 폭. **불릿만 있으면 그림 높이에 고르게 배치**(18pt) |
| `callout` | (선택) 맨 아래 결론 박스 |

강의자료 PDF의 다이어그램을 쓸 때는 해당 페이지를 이미지로 잘라 `발표/img/`에 저장하고 경로를 적는다.

### `summary` — 정리
| 필드 | 설명 |
|---|---|
| `items` | `[{ "no": "06", "head": "한 문장", "sub": "보충" }]` 단원 수만큼 |
| `closing` | (쓰지 않는다 — 인용·다음 강의 안내 금지) |

### `quiz-item` — 퀴즈 1문제 (덱 마지막에 3개)
하나를 쓰면 **[문제 슬라이드, 정답 슬라이드] 두 장**으로 펼쳐진다. 두 장은 배치가 같아서 넘기면 정답이 드러나는 것처럼 보인다.
진행: 문제 화면 → 각자 생각 20~30초 → 발표자가 넘겨 정답 공개 → 이유 설명.

```json
{
  "type": "quiz-item",
  "kind": "O / X",
  "q": "스프링 빈은 기본적으로 **요청마다** 새 객체가 만들어진다.",
  "code": "(선택) 문제에 필요한 코드",
  "choices": ["(선택) ① 보기", "② 보기"],
  "answer": "X",
  "reason": "스프링 빈은 기본이 싱글톤이다. 하나만 만들어 공유한다.",
  "time": "0:30",
  "script": ["문제 읽는 대사", "(20~30초 기다린 뒤 넘긴다)"],
  "cues": ["문제 슬라이드 연출"],
  "answerTime": "0:40",
  "answerScript": ["정답은 **X** 입니다.", "이유 설명 대사"],
  "answerCues": ["정답 슬라이드 연출"]
}
```

| 필드 | 설명 |
|---|---|
| `kind` | `O / X` · `단답` · `객관식` — 소제목에 `퀴즈 n / N · 유형`으로 표시 |
| `q` | 문제 문장 (30pt, 2줄까지) — 슬라이드 제목 |
| `code` / `choices` | 있으면 왼쪽 열에(코드 최대 20pt), 답 영역은 오른쪽 열. 없으면 답 영역이 전체 폭 |
| (O/X 자동) | `kind` 가 `O / X` 이고 코드가 없으면 O·X 큰 카드 두 장. 정답 슬라이드에서 정답 카드가 파랗게 |
| `answer` | 정답 — 파란 카드에 크게 |
| `reason` | 이유 — 회색 카드. 화면엔 2~3줄, 자세한 설명은 `answerScript`로 |
| `time` / `answerTime` | 문제 슬라이드(생각 시간 포함, 기본 0:30) / 정답 슬라이드(기본 0:40) |

- 퀴즈는 **2문제**, 출제 대상은 사용자가 고른 **핵심 주제**뿐(문제마다 `cues` 에 어느 주제인지 적기). 2문제 ≈ 2분 40초.
- 장 수 경고는 퀴즈 한 쌍을 1장으로 센다.

## 빌드 경고 목록

| 경고 | 해결 |
|---|---|
| 코드가 영역에 14pt로도 들어가지 않음 | 코드 줄이기(핵심 줄만), 블록 나누기, 다른 유형으로 |
| 코드 블록이 12줄 초과 | 핵심 줄만 남기기 (온라인 규칙) |
| 퀴즈 이유 설명이 영역을 넘침 | 화면 문장은 줄이고 자세한 설명은 `answerScript`로 |
| 제목이 1줄을 넘음 | 제목 줄이기 — 28pt까지 자동 축소 후에도 넘친 경우 |
| 설명 글이 영역을 넘침 | 불릿 줄이기·문장 다듬기 |
| 목차 설명이 김 / Q 문장이 2줄 넘음 | 문장 줄이기 |
| time·script 없음 | 채우기 |
| 총 시간이 상한 15분 초과 / 10분 미만 / 16장 초과 | 줄일 후보를 사용자에게 제안(핵심 주제는 유지) |
| 퀴즈가 2문제가 아님 | 핵심 주제 대상 2문제로 |
