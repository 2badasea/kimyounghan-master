# 발표자료 요청 입력 양식

사용자가 "발표자료 만들어줘"처럼 요청하면 **바로 만들지 않고, 먼저 아래 [보낼 양식]을 채팅으로 보낸다.**
사용자가 채워서 보내면 `<강의 폴더>/발표/요청서.md` 에 그대로 저장(기록)하고 작업을 시작한다.

- 양식에는 **사용자만 정할 수 있는 것**만 넣는다. 고정 규칙(아래 [입력 불필요])은 묻지 않는다.
- 사용자가 이미 요청 메시지에 적은 항목은 미리 채워서 보내고 "맞으면 그대로 두세요"라고 한다.
- 빈칸으로 돌아온 선택 항목은 기본값으로 진행하고, 무엇을 기본값으로 했는지 보고한다.
- 사용자가 양식 없이 바로 진행하라고 하면 필수 항목만 확인하고 나머지는 기본값으로 진행한다.

## [보낼 양식]

```
[발표자료 요청서]

■ 필수
1. 강좌명:                       (예: 스프링 입문)
2. 강의자료 PDF 폴더:              (예: C:\BadaDev\kimyounghan\스프링입문\김영한 - 스프링 입문)
3. 이번 발표 범위:                 (예: 전체 / 1~6장)
4. 내가 생각하는 핵심 2~4개:        (이게 맞는지 강의자료 보고 피드백해 줌 · 퀴즈 2문제는 여기서만 출제)
   1)
   2)
   3)

■ 선택 (비우면 기본값)
5. 스타일 버전:                    (기본 v1 — 토스 블루)
6. 꼭 넣을 내용:                   (슬라이드로 따로 보고 싶은 것, 비교하고 싶은 것)
7. 뺄 내용:                        (예: AOP, 톰캣)
8. 강의 밖 보충 요청:              (강의엔 없지만 넣고 싶은 것 — 화면에 "강의 밖 보충" 표시됨)
   ※ 보충은 시간이 늘어나는 주원인. 15분을 넘으면 줄일 곳을 같이 제안함
9. 실무 코드 참조:                 (안 함 / geumcheong_src / bucheon / cali/backend / cali/frontend — 구조만 재현)
10. 기타 요청:
```

## [입력 불필요] — 고정 규칙 (스킬이 자동 적용)

| 항목 | 고정값 | 근거 |
|---|---|---|
| 청중·환경 | 6명 스터디, 디스코드 화면공유, 초급 개발자·취준생·이직 준비생 | SKILL.md |
| 산출물 | 발표자용 pptx(노트에 대사 전문) + `_공유` pptx(노트 없음) + 발표대본.md, `<강의 폴더>/발표/` | SKILL.md |
| 겉모습 | 선택한 스타일 버전 규격(기본 v1) | styles/README.md |
| 표지 | 강좌명만, 발표일 없음, 발표자 이름만 | SKILL.md |
| 제목 | 단어 위주 간결형, 반말 문장 금지 | SKILL.md |
| 질문 | 답이 나오는 슬라이드 상단 띠, 대기 5~8초(채팅) | SKILL.md |
| 시간 | **상한 15분**(초안 13분 안팎, 보충 여유 2분) | SKILL.md |
| 퀴즈 | 마지막 **2문제, 핵심 주제(4번)만 출제**, 생각 20~30초 후 넘겨 공개, "생각할 시간" 문구 없음, 정답 대사 보충 3~5문장 | SKILL.md |
| 정리 | 단원별 한 줄, 글씨 크게, 인용·"다음 강의" 없음 | SKILL.md |
| 제외 | 면접·예상 질문, 라이브 데모 | SKILL.md |
| 회사 코드 | 화면에 띄우지 않음, 구조만 재현·이름 일반화 | SKILL.md |
| 발표자 | 이바다 | 덱 스펙 meta.presenter |

## 요청서 기록 형식 (`<강의 폴더>/발표/요청서.md`)

```
# {강좌명} 발표 요청서

> 받은 날짜: YYYY-MM-DD · 스타일: v1

(사용자가 채운 양식 그대로)

## 기본값으로 진행한 항목
- 5. 스타일 버전 → v1 (비어 있음)
```

이후 피드백 회차는 `작업_인계.md` 에 기록한다(요청서는 처음 받은 그대로 둔다).
