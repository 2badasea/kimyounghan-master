# 스타일 버전 목록

발표자료의 **겉모습(색·글꼴·크기·좌표)** 은 버전으로 관리한다. 내용 규칙(SKILL.md)·대본 규칙(script-format.md)은 버전과 무관하게 공통이다.

| 버전 | 이름 | 상태 | 토큰 파일 | 규격 문서 | 표본 |
|---|---|---|---|---|---|
| **v1** | 토스 블루 | **기본값**, 2026-10-04 고정 | `scripts/styles/v1.js` | [v1.md](v1.md) | 스프링 입문 (`examples/spring-intro.deck.json`) |

## 고르는 법

- 덱 스펙 `meta.style` 에 버전 이름을 쓴다. 생략하면 `v1`.
- 사용자가 버전을 말하지 않으면 **v1** 으로 만든다.
- 빌드 출력 첫 줄 근처에 `스타일: v1` 처럼 실제 적용된 버전이 찍힌다.

## 새 버전 만드는 법 (사용자가 다른 스타일을 원할 때)

1. `scripts/styles/v1.js` 를 복사해 `scripts/styles/v2.js` 를 만들고 토큰(COLOR·CODE·FONT·SIZE·GRID)을 바꾼다. **v1.js 는 고치지 않는다.**
2. `references/styles/v1.md` 를 복사해 `v2.md` 를 만들고 값·콘셉트·변경 이력을 새로 쓴다.
3. 이 표에 한 줄 추가한다.
4. 레이아웃 배치 자체가 달라야 하면(예: 제목 가운데, 다른 카드 모양) `build.js` 의 해당 렌더러에서 `STYLE_VERSION` 으로 분기한다. 토큰만 바뀌면 분기하지 않는다.
5. 표본 덱으로 빌드·렌더 검수 후 사용자 확인을 받고 상태를 "고정"으로 바꾼다.

## 버전 안에서의 수정

- 고정된 버전도 **작은 교정**(간격, 줄바꿈 계산, 자동 크기 조절 등)은 같은 버전 안에서 고치고 그 버전 문서의 변경 이력에 남긴다.
- 사용자가 "이전 모양이 더 낫다"고 하면 변경 이력을 보고 되돌린다.
