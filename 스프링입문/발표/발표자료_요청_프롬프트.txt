* 내가 생각하는 핵심
이 강의는 입문이라 전체 흐름을 입문자 수준에서 러프하게 훑는 거거든.
내가 봤을 때 중요한 건 일단
1) 스프링으로 요청 받고 응답하는 것
2) 컨트롤러/서비스/리파지토리로 데이터 저장하고 보여주는 것
3) 인터페이스로 리파지토리 구현체를 교체하는 것
4) 생성자로 주입하는 방식(DI)
이 정도라고 생각하는데, 강의자료 전체 참고해서 내용 구성해보고 내 생각이 맞는지 피드백도 좀 줘.
AOP는 빼자. 톰캣 얘기도 강의에서 중요한 부분은 아니라서 빼고.

* 구성할 때 넣었으면 하는 것
- 응답 방식 세 가지(정적 / MVC / API) 설명하고, 화면엔 없어도 @ResponseBody 대신 클래스에 @RestController 붙이면 생략 가능하다는 것도 보충해줘.
  @Controller랑 @RestController 역할 차이도. (전자는 화면 전환, 후자는 데이터 주고받는 쪽으로 많이 쓰는 걸로 알아)
- 인터페이스 개념을 초보자도 이해할 수 있게 간단하게 짚어주고, implements 하면 선언한 메서드 다 구현해야 한다는 것도.
  화면 좁으면 슬라이드 하나 더 만들어서 예시 코드도 보여줘. 회원가입 save가 카카오냐 네이버냐에 따라 구현체가 다른 식으로.
- 의존성 주입할 때 private final로 선언하는 이유랑, 실무에선 lombok 애너테이션(@RequiredArgsConstructor) 같이 쓰는 것도 넣어줘. 왜 그렇게 쓰는지까지.
- 주입 방식 세 가지(필드 / setter / 생성자) 차이랑 생성자 주입 권장하는 이유는 별도 슬라이드로.
- 빈 등록 두 가지 방법은 슬라이드 두 개로 나눠서 왼쪽엔 코드, 오른쪽엔 특징이랑 설명.
  실무에선 둘 다 같이 쓰는 걸로 아는데(컨트롤러/서비스/리파지토리는 컴포넌트 스캔, 설정 같은 건 자바 코드) 이것도 확인해서 보충해줘.
- DB 쪽은 순수 JDBC, JdbcTemplate, MyBatis, JPA, 스프링 데이터 JPA가 같은 select를 어떻게 다르게 쓰는지 강의 소스 기준으로 비교해서 보여줘.
  JPA랑 스프링 데이터 JPA 차이도 꼭 설명해주고.
- "저장소를 네 번 바꿨다. 서비스 코드는 몇 줄 바뀌었을까?" 질문은 설정 한 줄로 교체하는 슬라이드 상단에 같이 넣어줘.
  설정만 바꿔서 구현체가 바뀌는 원리는 대본에 설명 넣어주고.

* 스타일
- 흰 배경에 파랑/흰색 조합(Signal Blue #0057FF 베이스). 토스 UI 같은 느낌 좋아해.
- 폰트는 Pretendard.
- 소스코드는 포매터 맞춰서, IntelliJ처럼 주석이랑 코드 색 들어가게.
- 표지는 문장 말고 그냥 '스프링 입문' 처럼 강좌명만. 발표일은 넣지 마.
- 슬라이드 제목은 반말 문장 말고 단어 위주로 간결하게.
- 글씨 너무 작지 않게. 디스코드로 공유하면 화면이 뭉개지니까.
- 면접 질문이나 예상 질문 같은 건 넣지 마.

*  진행 방식
- 라이브 데모는 안 할 거야. 막히면 시간 손실이 너무 커.
- 퀴즈는 마지막에 3문제. 화면 보여주고 각자 20~30초 생각할 시간 준 다음에 내가 넘겨서 정답 공개하고 이유 설명하는 식으로.
  '생각할 시간' 같은 문구는 화면에 넣지 말고.
  문제는 너무 쉬운 거 말고 강좌 핵심이랑 연결되는 걸로.
  정답 설명할 때 보충할 내용은 대본에 따로 적어줘. (메시지 컨버터가 문자열/객체별로 뭐가 동작하는지, 싱글톤으로 같은 인스턴스를 공유한다는 게 뭔지랑 장점 같은 것)
